# LVS v0.3-alpha2: paper portfolio look-through

**Read-only research prototype; no transactions and no investment approvals.**
This extends the existing v0.3-alpha Git branch. Apply the patch to the same
project, install the editable package if necessary, and run pytest.

## Commands — Windows PyCharm PowerShell terminal

```powershell
.\.venv\Scripts\python.exe -m pytest -q

# If these two exposure snapshots have expired, re-fetch both. They are
# saved to the same data/lapidus.sqlite3 file used by the planner.
.\.venv\Scripts\python.exe -m lapidus_vaults exposures --vault 0x050cE30b927Da55177A4914EC73480238BAD56f0 --vault 0x1e9e47583f15D45a10Df48c0b1846E0492c795D7

# The older plan outputs weren't persisted. Run plan once with the same
# temporary, paper-only allowlist as before to save a plan ID:
.\.venv\Scripts\python.exe -m lapidus_vaults plan --capital-usdc 200 --allowlist data/paper_test_allowlist.json --limit 10

# No network call: combines last saved paper plan and stored exposures.
.\.venv\Scripts\python.exe -m lapidus_vaults portfolio-exposures
```

Optional `--plan-id ID` selects an older paper plan; `--max-age-hours N` changes
maximum age of source exposure snapshots (48 hours by default). Both arguments
apply only to the `portfolio-exposures` command. **When the planner fails to
allocate to either vault** (for example a directory change or failed screen),
its actual saved weights are used. Look-through does not invent allocations.

## Database additions

- `paper_plans`: append-only hypothetical plan header, total capital, wallet idle,
  submitted policy and UTC timestamp.
- `paper_plan_allocations`: vault-level paper allocations in **USDC base units**.
- `portfolio_exposure_analyses`: each analysis' source plan, exact exposure
  snapshot IDs, aggregation version, HHI and market totals.
- `portfolio_market_exposures`: each analysis' market ID, supported loan and
  collateral symbols, estimated proportional USDC exposure and contributing vaults.

Original `vault_snapshots`, `vault_screenings`, `exposure_snapshots`, and
`exposure_market_positions` tables remain intact; no schema migration that
rewrites old rows. Old, unsaved plans cannot be recovered retrospectively.

## Meaning and safeguards

- `80 USDC` deposited in a vault with `93.29%` market allocation corresponds to
  **approximately** `74.632 USDC` exposure to that lending market; it does not
  mean ownership of `74.632 USDC` of the collateral token.
- Uses `Decimal` and raw integer base units, not binary floats, for monetary math.
- Separates **wallet idle USDC** from **USDC idle inside a vault**.
- Reports both portfolio-wide market exposure and share of capital actually in
  lending markets. Market HHI uses the latter (shares sum to 1).
- Requires all funded vaults to have recent, fully reconciled direct-market
  exposure snapshots; incomplete/nested/truncated positions fail closed. The
  portfolio and its source snapshot IDs are retained for reproducibility.
- Two vaults can have the same market ID. This is shared credit-market exposure,
  **not** two independent investments.
- Different vault snapshots need not refer to the same chain block, and we do
  not yet RPC-verify indexed data; these are approximate paper exposures, not
  contemporaneous on-chain proofs of balances.
- **Does not** imply collateral ownership, investability, recoverability,
  withdrawal liquidity, credit loss likelihood, custody of funds, or safe APY.
- This version does not fetch live data inside `portfolio-exposures`; use
  `exposures` to refresh observations first.

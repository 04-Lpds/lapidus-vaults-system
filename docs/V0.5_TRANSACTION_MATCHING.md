# v0.5 — exact transaction-to-manifest matching (read only)

New command:

```powershell
.\.venv\Scripts\python.exe -m lapidus_vaults.transaction_match --manifest-id 1 --sequence 1 --tx-hash 0xREAL_BASE_TRANSACTION_HASH --allowlist data/paper_test_allowlist.json
```

This command checks a real Base mainnet transaction against one saved, integrity-checked proposal. It verifies the sender, destination, exact calldata, payable ETH value, chain ID, receipt success/confirmations, and receipt block relative to the plan snapshot. The result is recorded in `transaction_candidate_matches` in SQLite. It is **not** possible to use existing Anvil-only hashes with the mainnet command.

An exact match **does not establish prior authorization, safe execution, or completed financial reconciliation**. The module has no wallet connection, raw private key, transaction signing, broadcasting or ability to spend funds. The existing review manifest is informational, and freshness is not re-applied after a transaction is already mined. The pre-execution freshness gate must be evaluated before the user authorizes a transaction.

This is deliberately the next small building block: a correlation record for transactions the user may manually authorize in a future supported flow. A real-capital MVP still needs a human-reviewed transaction handoff, fresh-state feasibility and vault adapter checks, and actual pre/post asset-delta reconciliation. Do not fund the dedicated wallet solely on this milestone.

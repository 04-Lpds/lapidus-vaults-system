# v0.5 — read-only transaction receipt inspection

LVS now supports looking up an **already-broadcast** Base transaction hash using public HTTPS RPC. It inspects transaction and receipt identity, the signer, allowed method/destination/spender, receipt status, confirmation count, and wallet USDC/Morpho share balances at the receipt block.

```powershell
git pull --ff-only
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m lapidus_vaults.receipt_inspect --tx-hash 0xYOUR_64_HEX_CHARACTERS --wallet 0x8685F85E3afcE79310658FB09d85BB98ecFc7EdE --allowlist data/paper_test_allowlist.json
```

Use a **real Base transaction hash from that same wallet** for a meaningful result. The previous Anvil hash is not present on actual Base and will return pending/not found.

**Scope / limits:** This inspector does *not* create or sign transactions. It is not yet a true financial reconciliation: it does not compare an independently recorded pre-transaction balance or signed authorized plan against post-transaction receipts and token deltas. A receipt showing success does not alone establish a correct rebalance. No mainnet execution permission is provided.

## Updating the monitor scheduler window style

The old scheduled action used PowerShell without a window-hiding flag and might briefly flash a console. The installer now uses `-WindowStyle Hidden`. To apply the update after pulling:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\install_monitor_task.ps1
```

This re-registers the read-only task and resets its trigger. This change usually suppresses the flash, although Windows task context and policies may affect UI behavior.

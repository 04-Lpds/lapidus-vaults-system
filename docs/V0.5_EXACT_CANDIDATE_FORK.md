# v0.5-alpha — exact candidate fork integration

**Purpose:** close the gap between `unsigned_candidates.py` calldata and actual fork execution. This script reuses the production-oriented `build_rebalance`, `build_safety_plan` and `make_unsigned_candidates` functions. **Only** the local test adapter sends transactions, using a disposable Anvil actor and loopback RPC.

Workflow: fund Anvil actor via fork-only impersonation, seed 10 USDC in Gauntlet, calculate 40/40/20 rebalance, read current fork allowances, create unsigned calldata intentions, then submit **those unchanged candidate `data` bytes** in sequence to localhost Anvil. Every receipt is checked, USDC cash deltas verified, and the final wallet/vault holdings reconciled.

Fresh fork required. In Terminal 1:

```powershell
anvil --fork-url $env:BASE_RPC_URL --chain-id 8453 --host 127.0.0.1 --port 8545
```

In Terminal 2:

```powershell
git pull --ff-only
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m lapidus_vaults.fork_candidate_rebalance --usdc-holder 0x51c72848c68a965f66fa7a88855f9f7784502a7f
```

Expected: `FORK_ONLY_EXACT_CANDIDATES_REBALANCE_SUCCEEDED` and on-fork transaction receipts for each action, with final idle USDC matching the planner.

**Scope:** This validates exact candidate calldata in one specific healthy fork state. It does not yet establish mainnet liquidity, per-vault capacity, fresh gas budgets, financial risk safety, or proper mainnet transaction authorization. Do not submit the emitted unsigned transaction candidates to a real wallet. This module must never be used for live execution.

## Package organization plan

The current flat `src/lapidus_vaults` layout is legitimate for early prototypes but is getting hard to navigate. The next low-risk refactor should move code incrementally into these domains:

```text
lapidus_vaults/
  data/            # Morpho API clients, on-chain reads, persistence
  portfolio/       # positions, allocation policy, plan calculations
  transactions/    # ABI encoding, unsigned candidates, safety validation
  integrations/    # fork-only RPC and test scenarios
  cli/             # thin command-line entry points
```

Keep backwards-compatible `python -m lapidus_vaults.<existing_module>` wrappers during migrations; require passing unit tests and clean fork tests after each module move. Avoid introducing microservices or a full deployment stack for a small personal-capital MVP.

# Hypothetical vault interface diagnostic

Run against a public Base RPC endpoint with **no account funding**:

```powershell
$env:BASE_RPC_URL = "https://mainnet.base.org"
.\.venv\Scripts\python.exe -m lapidus_vaults.vault_diagnostic --wallet 0x8685F85E3afcE79310658FB09d85BB98ecFc7EdE --vault 0x050ce30b927da55177a4914ec73480238bad56f0 --usdc 10
```

Repeat with the second research vault `0x1e9e47583f15d45a10df48c0b1846e0492c795d7`.

This diagnostic has two intentional boundaries:

1. The **reusable** reads (wallet USDC/share/ETH balances, USDC allowance, pinned Vault V2 previews, fee oracle upper-bound for a 512-byte assumed transaction, and latest RPC gas-price quote) can also support later live preflight.
2. The **hypothetical amount** is test-only input: it is never interpreted as a real funded balance or allowance. No state overrides or fork transactions are attempted here; nonzero `eth_call` execution and gas unit estimation remain unverified. A fork-based integration test with controlled state will be a separate increment.

`getL1FeeUpperBound(512)` returns an upper bound **only for an unsigned transaction of size 512 bytes**, not for a future signed transaction of unknown size. A real execution path must encode the typed transaction and include full fees, capacity and liquidity gates. A successful `previewDeposit` or `previewWithdraw` is not evidence of executable capacity.

This command never stores credentials or broadcasts, and it never offers transaction authorization.

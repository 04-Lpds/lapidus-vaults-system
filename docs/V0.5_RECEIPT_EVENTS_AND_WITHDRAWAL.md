# LVS v0.5 — receipt event and manual withdrawal pilot

A verified Base transaction receipt contains transaction-scoped ERC20 Transfer logs. New `receipt_events.py` decodes those for exact USDC spent/received and vault shares minted/burned, and `live_deposit.check_receipt` now requires transaction-scoped logs **and** consecutive-block balances to agree. This avoids falsely including unrelated transactions' logs from the same block. It remains limited: a token can emit misleading events, and downstream adapter exposure needs independent accounting.

The existing local console additionally supports **Live withdrawal — manual MetaMask authorization** for the *first allowlisted vault* only, currently Gauntlet USDC Prime. This is a limited manual workflow, not autonomous withdrawal; quotes are capped at 10 USDC. `previewWithdraw`, actual share balance, individually simulated `withdraw(assets, wallet, wallet)`, ETH reserve and gas estimate must all pass at fresh state; the quote is rechecked before exposing calldata to MetaMask. A transaction is sent only after the visible button and a separate MetaMask confirmation.

**This withdrawal path has offline tests but has NOT been tested on live Base mainnet.** Do not authorize a live withdrawal until the fresh quote, requested assets, estimated shares, recipient and gas are reviewed. In particular, actual adapter liquidity could change between simulation and inclusion.

To confirm scheduled monitor sees the Gauntlet position, update code then run a *one-shot* monitor manually when the scheduled task is idle:

```powershell
git pull --ff-only
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m lapidus_vaults.monitor_once --wallet 0x8685F85E3afcE79310658FB09d85BB98ecFc7EdE --allowlist data/paper_test_allowlist.json
```

It prints `vault_estimated_assets_units` and `wallet_usdc_units` and saves full snapshot to `data/lapidus.sqlite3`. It may refuse concurrent execution if the scheduled task currently holds the lock; simply run again after that task completes. The scheduler itself keeps running every 15 minutes and requires no reinstall for this Python-only change.

The recorded USDC deposit transaction: `0xb112ce9cdf71491eefa56319a78f0bacfd038fa1d62e9af544f9b2eb390298c0`. The old already-stored `BLOCK_LEVEL_BALANCE_MATCH` record is historical and cannot automatically become an event-verified receipt merely by upgrading source code; future checks must use the new parser.

# v0.4-gamma — Fork-only withdrawal scenarios

This extends the 10 USDC local roundtrip with two withdrawal paths: a **2.5 USDC partial withdrawal**, followed by **redeeming every remaining share**. Unlike a fixed-asset withdrawal, full-share redemption should leave an exactly zero share balance. It compares previewRedeem against USDC actually received and reports gas units and any net difference in USDC after the roundtrip.

Use a **fresh Anvil fork** for each scenario, at `127.0.0.1:8545`. The script uses only the pre-existing localhost-restricted ForkRPC test client and an Anvil-only impersonated holder.

```powershell
git pull --ff-only
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m lapidus_vaults.fork_exit_scenarios --vault 0x050ce30b927da55177a4914ec73480238bad56f0 --usdc-holder 0x51c72848c68a965f66fa7a88855f9f7784502a7f
```

Stop and restart Anvil before running the same test against:

`0x1e9e47583f15d45a10df48c0b1846e0492c795d7`

If a withdrawal or redemption reverts, the test reports the failing step and does not treat the scenario as successful. If previewRedeem and actual USDC balance changes disagree, it fails reconciliation. Expected fees and rounding may cause a small net difference from initial USDC; that is reported instead of silently ignored.

**Important:** A successful fork scenario proves those specific actions worked for those amounts in the fork state. It does not prove adequate liquidity for larger withdrawals or future market conditions, and it is not an authorization to execute live capital movements. Liquidity-constrained and paused-vault negative tests remain separate future work.

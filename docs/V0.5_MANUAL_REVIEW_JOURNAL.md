# LVS v0.5 — durable manual transaction review

The new `lapidus_vaults.transaction_review` module writes a hashed, read-only transaction review manifest into SQLite. This is a **record of proposed intents**, not an approval or executable bundle. Its SHA-256 is a canonical-content integrity identifier, not an authorization signature.

```powershell
git pull --ff-only
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m lapidus_vaults.transaction_review --wallet 0x8685F85E3afcE79310658FB09d85BB98ecFc7EdE --allowlist data/paper_test_allowlist.json --max-action-usdc 100
```

When the wallet has no USDC or ETH, the command should create an empty manifest successfully. For funded portfolios, the existing `build_live_readonly_plan` fee-readiness gate still applies. Manifests capture the snapshot block, allowlist, per-action cap, exact **unsigned** calldata candidates and action dependencies.

**No MetaMask connection yet.** No wallet private keys, browser signing, wallet redirect, encoded nonce, live transaction simulation or broadcasting. Do not copy manifest calldata into a transaction to submit. Before live use, add EIP-1559 construction, recent-state sequential simulation, adapter liquidity/capacity checks, short expiry/staleness invalidation, explicit wallet authorization, transaction-hash-to-manifest reconciliation, receipt/event checks, and pre/post balance delta verification.

Existing `receipt_inspect` is independent and only verifies a real Base transaction/hash, not whether it was approved by an LVS manifest.

# Adversarial review of PR #5

Reviewed implementation: `59c34f26529d658422ecea864ce47cc688a2e096`.
These are code-level findings, not an independent security certification.

## Threat model

The policy, Python process, key provider, SQLite files and operating system are
trusted. This review considers buggy/direct API callers, concurrent invocation,
administrative halts, changing chain state, RPC failures and process crashes.
The policy is not an on-chain sandbox against a compromised process. No real
private keys were accessed and no transaction was broadcast during this review.

| High | Campaign authority checked only before slow signing/RPC work. Halting a campaign during signing still reached the send transport. A persisted binding for a later step also did not independently establish that prior steps were confirmed. | Recheck exact binding, metadata, candidate, current-step activity, predecessor receipts and matching confirmed journal hashes. The first adversarial cases were run before their corresponding fixes. They
reached an intercepted forbidden signature/send or failed to reject the unsafe
reservation/allowance/budget. After repairing a test fixture to match persisted
JSON list serialization, halt and expiry cases reproduced at the actual send
boundary. Passing tests are therefore not merely mirrors of the new guards.

## Recovery and concurrency behavior

- Crash before signature/hash persistence never permits a blind replacement.
  A bound quote without a journal remains a manual-review halt.
- The deterministic hash is committed before the final checks and send. A crash
  before network I/O can therefore leave a `SUBMITTED` hash that is absent from
  the node. This is conservative uncertainty, not evidence it was sent. Recovery
  only looks it up; **never resend it** or generate a replacement automatically.
- A duplicate direct invocation is rejected before signing when a journal entry
  already exists. Concurrent invocations may both reach signing before either
  reserves; SQLite allows only one reservation/send. Raw signed bytes are not
  returned to an external caller by this path.
- A halt that commits before the final DB lock prevents sending. A halt requested
  after the send critical section begins waits for that section and cannot
  cancel an in-flight network request. The stop file also cannot retract an
  already submitted transaction.
- A crash between journal confirmation and campaign receipt bridging deliberately
  blocks subsequent execution. Automatic atomic bridge repair is not implemented.
  Manual investigation must retain hashes/bindings, not delete or rewrite them.

## Unresolved risks and release decision

**Ready to begin controlled local-fork validation after setup; not fork-validated
and not ready for production or recurring live execution.**

1. An EIP-1559 signature has no on-chain expiration. A node may include an
   already-broadcast transaction much later than the local 90-second deadline.
   ERC-4626 methods used here have no minimum-share/maximum-burn parameters.
   Pre-send checks and post-receipt halts do not enforce on-chain slippage or
   cancel a pending transaction. A contract execution guard would need separate
   ownership/authorization design and independent review.
2. Reads are pinned by block height, not hash; receipt recovery currently accepts
   the first matching receipt without a finality/confirmation policy. Reorgs or
   dishonest RPC evidence can invalidate an apparently confirmed step. Basic
   API/RPC consistency is not provider independence or economic authorization.
3. The L1 budget uses a conservative size floor/envelope allowance and 2x current
   oracle value, not a hard future-fee cap. Base operator fees or future chain
   fee-model changes are not independently bounded. Validate actual fork
   receipts and oracle availability; fail closed if it is unavailable.
4. Keys remain inside the Python process. Policy/DB access integrity and exclusive
   use of one dedicated EOA with one execution DB are required. Independent
   processes or external users of the same key can race the node nonce after
   the final read. No distributed signer lock or external custody boundary exists.
5. The dedicated EOA owns the traded assets, receives proceeds and pays gas.
   No authority to trade a distinct strategy owner's position has been proven.
   Relayer/smart-account/delegation support is intentionally absent.
6. Persistent daily spend/loss budgets, vault risk approval, monitoring and
   operational recovery review are still needed. A vault allowlist is not a
   safety assessment. Morpho V2 `maxWithdraw` remains diagnostic per existing
   protocol assumptions; simulation does not guarantee future exit liquidity.

  regression cases over the initial PR's 397). Codex escalation was needed for
  the existing loopback HTTP console tests. No chain broadcasts were performed.

- `.venv/bin/python -m pip check`: passed; no broken requirements.
- `git diff --check`: passed.
- No linter/type-checker is configured in the repository.
- Real Anvil fork rehearsal: **not run**; executable missing. Pinned installation
  procedure and exact artifact digest are documented separately. Python 3.10
  execution remains for CI; this environment's validation used Python 3.12.

The final review also added a head re-read after slow safety queries: advancing
more than 10 blocks during nonce/oracle/balance reads now expires the
transaction even if the 90-second wall-clock deadline has not yet elapsed.
Transport-level tests cover nonce envelopes and credential-safe failure
tracebacks in addition to the higher-level signer mocks.

# LVS v0.4-alpha — read-only Base RPC verification

This is the first operational component of LVS's forthcoming capital allocator. **It does not sign, send, simulate, or authorize any transactions.** It cannot move funds. It requires only an HTTPS Base RPC URL and public vault/wallet addresses.

## What is verified (and what is not)

For each requested Morpho Vault V2 on Base, the command:

1. Calls `eth_chainId` and requires **8453**; fetches one block number.
2. Checks that both the vault and expected native Base USDC addresses have contract bytecode at that block.
3. Checks `asset()` on the vault and `decimals()` on USDC to confirm the underlying is **native Base USDC with 6 decimals**, not bridged USDC or another token.
4. At the **same pinned RPC block**, reads the vault's `totalAssets()` and `totalSupply()`.
5. Fetches Morpho API vault config/state and compares contract and token identity, indexed block age, total assets and total shares. It reports any discrepancy beyond the configurable tolerance.
6. With optional `--wallet ADDRESS`, reads `USDC.balanceOf(wallet)`, `vault.balanceOf(wallet)` (vault shares), and `vault.convertToAssets(shares)` (estimated asset value of the shares).
7. Appends the read-only observation to `rpc_vault_verifications` in SQLite, including block numbers, source values and reasons for review.

**Limitations:** Different API and RPC blocks imply that differences can be normal due to accrual, fee minting or indexer lag. A basic totals match is not an audit of underlying adapters, yield, withdrawal liquidity, borrower solvency, vault governance, oracle security, or executable transactions. The `MATCHED_BASIC_READS` status is **not an investment approval**. RPC is still provided by a trusted third-party endpoint; later versions should support a second independent provider and a stronger block-consistent adapter reconciliation. `convertToAssets` is an estimate, not a promise of withdrawability. This is not a rebalancing engine yet.

## Quick start — Windows PowerShell

1. Close DB Browser for SQLite if it has any active edits, and install/reinstall the current editable Python project if needed:

```powershell
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
.\.venv\Scripts\python.exe -m pytest -q
```

2. Set an RPC endpoint for this terminal session. For initial light testing, Base publishes a **rate-limited** HTTPS endpoint. Production should use a reliable provider; if yours includes a secret API key, keep it out of Git and chat messages.

```powershell
$env:BASE_RPC_URL = "https://mainnet.base.org"
```

3. Verify one already-researched vault (Gauntlet USDC Prime):

```powershell
.\.venv\Scripts\python.exe -m lapidus_vaults.rpc_verify --vault 0x050cE30b927Da55177A4914EC73480238BAD56f0
```

Or verify all the vaults in your existing paper allowlist:

```powershell
.\.venv\Scripts\python.exe -m lapidus_vaults.rpc_verify --allowlist data/paper_test_allowlist.json
```

Once you've chosen a **public address** for a dedicated wallet, add `--wallet 0xYOUR_PUBLIC_ADDRESS` to show its native Base USDC balance and vault share positions. **Never enter a private key, seed phrase, or recovery phrase** into this command or the project.

The provider reads are synchronous (roughly 5-10 RPC calls per vault, plus optional wallet calls); public endpoints may return rate limits. The command uses only `eth_chainId`, `eth_blockNumber`, `eth_getCode`, and `eth_call`, and all stateful reads are tied to the selected block number. One failing identity check aborts the affected query; discrepancy warnings are saved with `REVIEW` status. No automatic retry or transaction fallback.

## View the saved results

In DB Browser, choose **Execute SQL** and run:

```sql
SELECT id, created_at, vault_address, rpc_block,
       api_indexed_block, status
FROM rpc_vault_verifications
ORDER BY id DESC;
```

`details_json` preserves the checked values and optional public wallet address. The RPC URL is **never stored**. The local database is excluded from Git by `.gitignore`.

## Architecture and Rust

This first v0.4-alpha increment uses the existing `httpx` dependency to perform read-only EVM JSON-RPC calls in Python so the ABI, safety checks and tests remain transparent. The existing `rust/chain-worker` remains a separate **read-only Alloy connectivity probe**. We'll move validated on-chain reads and later preflight/reconciliation into Rust once that worker is compiled and tested with Cargo; we won't introduce a signer merely to verify state.

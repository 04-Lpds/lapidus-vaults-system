# LVS local integrated review console — first UI slice

A minimal Python HTTP server binds only to `127.0.0.1:8765`. It serves an internal browser page that can ask MetaMask to show accounts and network ID, and it connects existing LVS modules: pinned RPC/Morpho verification -> safety plan -> capped unsigned calldata -> SHA-256 manifest -> SQLite journal. It does not create a MetaMask transaction or sign anything.

From the project root:

```powershell
git pull --ff-only
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m lapidus_vaults.local_console --wallet 0x8685F85E3afcE79310658FB09d85BB98ecFc7EdE --allowlist data/paper_test_allowlist.json
```

Open `http://127.0.0.1:8765/` in the browser with MetaMask installed. Click **Connect MetaMask (identity only)** to request account and Base chain ID. Click **Prepare & journal proposal** to obtain a verified **read-only** manifest. It does not require an unlocked wallet to prepare a proposal; that design is intentional so preparation and wallet authorization remain separate.

`Ctrl+C` in the terminal shuts down the local server.

Security boundaries: loopback interface; fixed Host allowlist; POST token check; Origin check; short request body; no secrets printed, no send endpoint and no transaction submission call in the browser. Local machine compromise or malicious browser extensions are outside this model. The token protects only this local session and is not durable authorization.

**Not yet live-capital-ready.** The next phase must implement independent pre-deposit liquidity/capacity assessment, stateful simulation and freshness at every step, bounded EIP-1559 transactions, explicit per-transaction MetaMask confirmation, receipt-linked balance reconciliation and fail-stop recovery. The console intentionally shows unsimulated calldata only for review.

The initial wallet is empty, so the expected manifest includes `candidates: []`. Do not deposit funds into vaults from this UI.

# LVS v0.3-alpha: Vault V2 underlying exposure inventory

Status: **research prototype; read-only; not an investment recommendation**.

## What's added

- `MorphoClient.v2_exposures(chain_id, vault_address)` uses documented Morpho GraphQL adapter and position query.
- `normalize_exposures()` creates raw-base-unit market positions and separately records nested adapters.
- `exposures --vault 0x...` lists current direct market positions, their share of total vault assets, and explicit warnings for nested/unreconciled/truncated data.
- `exposure_snapshots` + `exposure_market_positions` SQLite tables retain every query's raw source data for reproducibility.
- Automated offline tests exercise parsing, failure modes, query shape, CLI, and SQLite persistence.

## Run on an existing v0.2 project

Use an ordinary new branch in **the same Git repository**. Apply the separately provided `.patch`, reinstall editable package if necessary, then run tests. You do not need to create another PyCharm project.

```powershell
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m lapidus_vaults exposures --vault 0x050cE30b927Da55177A4914EC73480238BAD56f0
```

For two vaults, supply `--vault` twice. Limit to 10 per call in this alpha. This first step **does not automatically rank or select candidates**.

## Interpretation constraints

- Base USDC only in the surrounding investment workflow. This command currently validates Base chain, but **does not validate the vault's loan asset**; use a previously screened USDC vault address.
- Position amounts are supplied assets, not risk-weighted losses. Collateral token is a **borrower collateral risk factor**; it is NOT a direct holding of that token by the depositor.
- Market exposure sums exclude nested vault adapters until recursive look-through is implemented.
- Adapter caps/risk-ID caps are *limits*, not actual positions; they are not included as capital exposures.
- The query requests at most 100 adapters and 100 positions per adapter; a full page triggers a possible-truncation warning. Pagination must be added before large-scale unattended monitoring.
- API observations are **not verified against live on-chain RPC state**; they may be stale or temporarily inconsistent.
- An unequal adapter-assets / total-assets reconciliation triggers a warning instead of silently assuming correctness.
- We store raw integer token units as strings in SQLite; no floating point currency arithmetic.
- No paper portfolio optimiser or transaction execution in this step; v0.2 `plan` still works independently.

# v0.5-alpha — manually inspectable unsigned calldata candidates

This milestone introduces `unsigned_candidates.py` and an opt-in `--show-unsigned-candidates` CLI flag. The encoder consumes the existing `SafetyPlan` and produces unsigned, UNSIMULATED ERC-20 `approve`, ERC-4626 `deposit`, and ERC-4626 `withdraw` call data.

**Live read-only inspection of an unfunded wallet:**

```powershell
git pull --ff-only
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m lapidus_vaults.live_readonly_plan --wallet 0x8685F85E3afcE79310658FB09d85BB98ecFc7EdE --allowlist data/paper_test_allowlist.json --show-unsigned-candidates --max-action-usdc 1000
```

You should see `unsigned_candidates: []` while the wallet is empty. The same command uses real pinned-block Morpho API/RPC verified holdings and on-chain allowance observations; the latest network gas quote is separately labeled.

**Safety model:** Allowlisted Base vault addresses only; EVM chain ID 8453; zero payable ETH; bounded USDC per action (default 1000 USDC); deterministic nonce-free action sequencing; receiver and withdrawal owner strictly equal to the observed wallet; approval spender only the requested allowlisted vault. Each candidate reports its sequence and dependencies.

**Not an execution pathway.** Candidates contain neither a nonce nor gas pricing or a signature, are NOT simulated and are not considered safe to sign or submit. Morpho V2 adapter liquidity, caps, fee limits, replay protection, EIP-1559 transaction construction, per-step on-chain state refreshing and receipts still need work. Never copy an unsigned candidate into a wallet to send real funds on this evidence alone. In particular, `maxWithdraw` and `maxDeposit` for Morpho V2 do not establish liquidity or capacity.

The existing `fork_cross_rebalance` runs separately on localhost using Anvil's test-only accounts, not personal capital.

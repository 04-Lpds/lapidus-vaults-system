# v0.5 MVP — verified read-only live planner

`python -m lapidus_vaults.live_readonly_plan` combines:

1. Existing manually selected Base USDC allowlist.
2. Morpho API vs pinned-block RPC basic verification (`read_wallet_snapshot`).
3. Wallet USDC and vault shares from the pinned block, and USDC allowances to each vault at that same block.
4. Pinned ETH balance and a separately labeled latest-state gas price quotation.
5. Existing `build_rebalance` and non-executable `build_safety_plan`.

**Command (unfunded wallet is fine; may show no actions):**

```powershell
git pull --ff-only
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m lapidus_vaults.live_readonly_plan --wallet 0x8685F85E3afcE79310658FB09d85BB98ecFc7EdE --allowlist data/paper_test_allowlist.json
```

Set `BASE_RPC_URL` to your HTTPS Base RPC URL before running it. A failed API/RPC consistency check causes fail-closed planning; retry once synchronized. Do **not** fund or deploy real capital yet.

The latest-state gas price is doubled as an intentionally simple spending *ceiling assumption*; per-step gas caps and fixed L1 budget are policy constants, **not a fee quote or assurance of sufficient funds**. A 0.002 ETH reserve is required before planned activity. No live transactions, signing, private keys, transaction calldata, or approval messages are produced.

**Next live MVP gates:**
- Need exact unsigned tx calldata for explicit user wallet inspection and authorization, caps and preconditions
- Must confirm liquidity/capacity via Morpho V2-specific sources (maxWithdraw always returns zero)
- Re-simulate all steps sequentially against fork state; recheck real chain before each signed step
- Observe receipt status, reconcile positions and errors, generate auditable journal
- Halt on failed or stale steps, reread and replan
- Keep initial deployment tiny and manually authorized

The code does not imply deposited USDC is free of vault, counterparty, oracle, or depeg risk.

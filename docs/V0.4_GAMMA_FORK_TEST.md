# LVS — local Base fork roundtrip integration harness

This is a **development-only integration harness**, unlike the reusable production-facing read-only preflight and diagnostic modules. It sends test transactions only to an ephemeral Anvil process listening on loopback, never to Base mainnet. Anvil fetches read-only historical state through an upstream Base RPC provider. The integration harness deliberately permits transaction methods only through its separate local-fork client; the production `ReadOnlyRPC` still forbids broadcasts.

## Prerequisites

Install Foundry/Anvil locally and have a working Base archive-capable RPC URL. Use the publicly available `https://mainnet.base.org` only if its rate limits support forking; a private provider is often more dependable. Set your upstream RPC URL in the PowerShell session, **do not commit it**.

Terminal A:

```powershell
$env:BASE_RPC_URL = "https://YOUR_BASE_RPC_ENDPOINT"
anvil --fork-url $env:BASE_RPC_URL --chain-id 8453 --host 127.0.0.1 --port 8545
```

Terminal B:

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m lapidus_vaults.fork_roundtrip --vault 0x050ce30b927da55177a4914ec73480238bad56f0 --usdc-holder 0xVERIFIED_USDC_WHALE --amount-usdc 10
```

The `--usdc-holder` must be a **verified** Base account with at least 10 native USDC at the fork block, and it must be possible to impersonate it. This is a test-only impersonation on your own Anvil fork. Do not enter any private keys. Replace `0xVERIFIED_USDC_WHALE` with the actual address of a suitable public USDC token holder. The program funds a standard Anvil test actor with fork-local ETH, impersonates the holder to transfer USDC, approves the vault, deposits 10 USDC, withdraws 10 USDC, and checks token/share deltas. It prints gas **units used**, not a mainnet L1+L2 all-in fee.

Repeat against Galaxy using `--vault 0x1e9e47583f15d45a10df48c0b1846e0492c795d7`. Restart Anvil between vault runs to reset the fork state.

If deposits or withdrawals revert, the command reports failure: the result may indicate actual vault restrictions, fees, capacity, or a required call route. Do **not** treat failures as evidence that all Vault V2s are invalid. If withdrawal of exactly 10 USDC fails after deposit, this could also reflect fees, precision, or liquidity constraints. Do not disable safeguards to force a success.

The harness rejects non-loopback RPC addresses, rejects wrong chain ID, requires verified vault identity and native USDC asset, limits test amounts to 1–10 USDC, checks transaction receipts, and has no access to your wallet credentials.

## Production reuse

The production system should reuse **balance/allowance checks, fee estimators, and post-transaction reconciliation logic**, not the impersonation or `eth_sendTransaction` calls in this harness. Future production execution must have a separately designed, manually authorized signing flow. This is **not** yet evidence of a successful fork transaction until you run the integration scenario and report the output.

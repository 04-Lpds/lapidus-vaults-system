# LVS v0.4-gamma — read-only Morpho Vault V2 preflight

Preflight has **no signing, approvals, or broadcasting**. A historical `eth_call` and an `eth_estimateGas` are not an execution guarantee.

## Critical Morpho V2 difference

Morpho Vault V2 **always returns zero** for `maxDeposit`, `maxMint`, `maxWithdraw`, and `maxRedeem`. These ERC-4626 methods cannot be used as live capacity limits. The current preflight deliberately ignores them. Instead, it observes USDC allowance, shares, ERC-4626 previews, pinned `eth_call` simulation, and current-state gas estimate. A successful simulation is not an independent assessment of deposit caps, gates, liquidity adapter, or force-deallocation paths.

**Status `STATIC_PASS_LIMITS_UNVERIFIED` is NOT an execution approval.** Production capacity calculation requires Morpho V2 adapter/cap and liquidity checks based on fresh on-chain state, as described in the Morpho SDK docs.

See https://docs.morpho.org/developers/earn/tutorials/assets-flow/ and https://docs.morpho.org/developers/contracts/morpho-vaults-v2/.

## L1 + L2 fee budgeting

Gamma uses `eth_estimateGas` (current node state), `eth_gasPrice` (current fee quote), and pinned `eth_call` to Base GasPriceOracle `0x420000000000000000000000000000000000000F`, calling `getL1FeeUpperBound(uint256)`.

A **provisional** unsigned transaction size (max of 512 bytes or calldata bytes plus 256) is supplied to the oracle; the returned result upper-bounds the fee **for that assumed size**. Because we do not yet serialize a complete unsigned transaction, the size assumption and resulting estimate are **not a proven upper bound for an eventual signed transaction**. Gamma applies a 2x buffer to combined L1+L2 quote and checks a minimum ETH reserve separately. It does not include a complete sequential, EIP-1559 or operator-fee forecast. Refuse real execution until proper typed-transaction encoding and complete network-fee handling are introduced.

See https://specs.optimism.io/protocol/fjord/predeploys.html.

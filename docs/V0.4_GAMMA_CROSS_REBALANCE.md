# LVS v0.4-gamma — cross-vault local fork rebalance

This integration scenario uses **the actual `build_rebalance` wallet allocator** with its existing two-vault 20%-idle / 40%-per-vault cap policy. The synthetic *wallet setup* is fork-only, but target calculation is production-reusable.

Workflow on a **fresh** Anvil fork:

1. Impersonate the validated USDC holder **only locally** and transfer 10 USDC to the Anvil test actor.
2. Approve and deposit 10 USDC into Gauntlet.
3. Observe actual fork USDC and share balances, convert holdings to estimated assets using on-chain `convertToAssets`, and invoke `build_rebalance`.
4. Order negative deltas (withdrawals) before positive deltas (deposits).
5. Withdraw the requested amount from Gauntlet; confirm USDC was actually received.
6. Approve and deposit the positive delta to Galaxy **only after cash is available**.
7. Read both vault share balances and wallet USDC, check idle target exactly and share value deviations within two USDC base units.

Approximate allocation for a 10 USDC initial portfolio: Gauntlet 4, Galaxy 4, idle 2. Exact raw units can differ because of share conversion.

Commands, in the LVS project Terminal 2:

```powershell
git pull --ff-only
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m lapidus_vaults.fork_cross_rebalance --usdc-holder 0x51c72848c68a965f66fa7a88855f9f7784502a7f
```

**Restart Anvil in Terminal 1 before the integration test** so it has a fresh fork. This script refuses existing test-actor USDC or vault shares; it does not re-run safely on an already modified fork. The `--fork-rpc` transport inherited from ForkRPC only accepts loopback endpoints, and all writes target localhost. No real wallet key, mainnet transaction, or signer is involved.

### Scope limits

This only tests a single immediate withdrawal-to-deposit rebalance at one fork state. Morpho V2 capacity, liquidity under stress, queued exits, slippage/fees and changing state still need production-grade verification. Planner asset values remain estimates. The fork's `eth_sendTransaction` calls are test-only and must not be reused as a live executor.

The scenario reports actual gas units for withdraw and deposit, but not L1/L2 network fee totals; those require separately encoded transactions and correct fee accounting.
